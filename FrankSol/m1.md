[Week 4][Medium] Missing ATA Creation Causes DoS for First-Time stake Users

## Finding

**Week**: 4
**Researcher**: @snufflesrea , [@snufflesrea](https://x.com/snufflesrea)
**Severity**:  Medium 
**Category**: dos
**Affected function(s)**: [stake]

## Description

The `stake` instruction requires `user_franksol_ata` — the user's Associated Token Account for frankSOL — to already exist before the instruction is called. The account constraint is declared as:

```rust
pub struct Stake {
    #[account(mut)]
    pub user: Signer,
    #[account(mut, seeds = [POOL_SEED], bump = pool.bump)]
    pub pool: Account<Pool>,
    /// CHECK: Vault PDA holding SOL.
    #[account(mut, seeds = [VAULT_SEED], bump = pool.vault_bump)]
    pub vault: UncheckedAccount,
    #[account(mut, seeds = [FRANKSOL_MINT_SEED], bump)]
    pub franksol_mint: Account<Mint>,
    /// CHECK: PDA signing mint CPIs.
    #[account(seeds = [MINT_AUTH_SEED], bump = pool.mint_auth_bump)]
    pub mint_authority: UncheckedAccount,
    #[account(
        mut,
        token::mint = franksol_mint,
    )]
    pub user_franksol_ata: Account<TokenAccount>, // this may not be exist yet
    #[account(
        init_if_needed,
        payer = user,
        space = 8 + core::mem::size_of::<UserPosition>(),
        seeds = [USER_POSITION_SEED, user.address().as_ref()],
        bump
    )]
    pub user_position: Account<UserPosition>,
    pub token_program: Program<Token>,
    pub system_program: Program<System>,
}
```
There is no init_if_needed on this account. Anchor will attempt to deserialize it as a fully initialized TokenAccount (165 bytes) during constraint validation. If the account does not exist — which is guaranteed for any first-time user — the runtime finds a 0-byte account where 165 bytes are expected and immediately throws AccountDataTooSmall, rejecting the transaction before a single line of handler() runs.

This means every brand new user is permanently blocked from staking unless they know to separately create their ATA before calling stake. There is no on-chain mechanism, no instruction, and no documentation in the program that would guide them to do this. The program's own stake instruction — the primary user-facing entry point — is broken for all first-time callers.

Compare to user_position, which correctly uses init_if_needed. The same pattern was not applied to user_franksol_ata, creating an inconsistency where position creation is seamless but token account creation is not.

## Impact
- Every first-time user is DoS'd — a new wallet calling stake will always receive AccountDataTooSmall with no actionable error message
- There is no fallback or recovery path within the program; the user must know to call create_associated_token_account out-of-band before staking, which is not documented or enforced anywhere
- Wallets and frontends that construct the stake transaction without pre-checking ATA existence will silently fail, degrading UX and potentially causing users to lose gas fees on repeated failed attempts
- Severity is Medium — no funds are at risk and the program remains exploitable by a knowledgeable user, but the primary entry point is non-functional for the expected common case

    let manifest_dir = env!("CARGO_MANIFEST_DIR");

        candidate_paths.push(PathBuf::from(target_dir).join("sbf-solana-solana/release/stake_v2.so"));

    for path in candidate_paths {
        if let Ok(bytes) = fs::read(path) {

fn send_ix(
    svm: &mut LiteSVM,
    payer: &Keypair,
    instruction: Instruction,
) -> litesvm::types::TransactionResult {
    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[payer])
        .expect("transaction should sign");
    svm.send_transaction(tx)
}

fn read_pool(svm: &LiteSVM, pool: &Pubkey) -> Pool {
    let account = svm.get_account(pool).expect("pool account should exist");
    assert_eq!(&account.data[..8], Pool::DISCRIMINATOR);
    *bytemuck::from_bytes::<Pool>(&account.data[8..8 + mem::size_of::<Pool>()])
}

## Recommended Fix
Add `init_if_needed` to `user_franksol_ata` so the program creates the ATA transparently on first stake, matching the pattern already used for user_position. This also requires adding associated_token_program to the accounts struct:
```rust
#[account(
    init_if_needed,               // ✅ creates ATA on first stake
    payer = user,
    associated_token::mint = franksol_mint,
    associated_token::authority = user,
)]
pub user_franksol_ata: Account<TokenAccount>,

// Add to accounts struct:
pub associated_token_program: Program<AssociatedToken>,
```
This is a single constraint change that eliminates the DoS entirely — the program atomically creates the ATA and completes the stake in one transaction, with no burden on the caller.Sonnet 4.6
